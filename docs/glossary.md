# 用語集

全テキストで**同じ言い回し**を使うための辞書。
初出時はここの定義文をベースに書く（そのままコピーしてよい）。

サポート AI もこのファイルを参照して、説明の言い回しを揃えてください。

---

## 共通（コンピュータ・開発全般）

| 用語 | 定義文（初出時にこう書く） | たとえ |
|------|--------------------------|--------|
| プログラム | コンピュータへの指示を、決まった書き方で並べたもの | 料理のレシピ |
| ソースコード | 人間が読み書きするために書いたプログラムの文章そのもの | レシピの紙 |
| 実行する | 書いたプログラムをコンピュータに読ませて、実際に動かすこと | レシピどおりに作る |
| ファイル | 名前を付けて保存された1つのデータのまとまり | — |
| ディレクトリ | ファイルをまとめて入れておく入れ物。Windows の画面上では「フォルダ」と表示される | 引き出し |
| パス | ファイルやディレクトリの場所を表す文字列 | 住所 |
| 絶対パス | 一番上から辿って書いた、場所を一意に決めるパス | 「東京都〜」から書いた住所 |
| 相対パス | いまいる場所を基準にして書いたパス | 「ここから2つ隣」 |
| 拡張子 | ファイル名の末尾に付く `.html` `.js` などの部分。ファイルの種類を表す | — |
| ターミナル | 文字でコンピュータに命令するための画面。Windows では PowerShell、macOS では「ターミナル」 | 受付窓口 |
| コマンド | ターミナルに打ち込む命令 | — |
| エディタ | ソースコードを書くための道具。このテキストでは VS Code を使う | — |
| ライブラリ | 他の人が作った、便利な機能のまとまり。自分のプログラムから呼び出して使う | 出来合いの部品 |
| フレームワーク | アプリの土台となる、大きな作りかけの構造。決められた場所に自分のコードを入れて完成させる | 建物の骨組み |
| パッケージ | 配布できる形にまとめられたライブラリ | 箱に入った部品 |
| 依存関係 | そのプログラムを動かすために必要な、他の人が作った部品のこと | — |
| パッケージマネージャ | ライブラリのインストール・更新・削除を管理する道具。npm や pip がこれにあたる | 部品の発注係 |
| バージョン | ソフトウェアの版。`v22.3.1` のように数字で表す | — |
| バグ | プログラムの間違い。意図どおりに動かない原因 | — |
| デバッグ | バグの原因を見つけて直す作業 | — |
| エラー | 実行中に問題が起きたことをコンピュータが知らせてくるメッセージ | — |
| PATH | ターミナルがコマンドを探しに行く場所の一覧。ここに登録されていないとコマンドが見つからない | 電話帳 |
| 環境変数 | OS 全体やターミナル全体で共有される設定値。PATH もそのひとつ | — |
| 環境構築 | プログラムを書いて動かせる状態を作る準備作業 | — |
| リポジトリ | プログラムのソースコードと、その変更履歴を保管する場所 | — |
| Git | ソースコードの変更履歴を記録・管理する道具 | セーブ機能 |
| GitHub | Git のリポジトリをインターネット上に置いて共有できるサービス | — |

## Web

| 用語 | 定義文 | たとえ |
|------|--------|--------|
| ブラウザ | Web ページを見るためのソフト。Chrome、Edge、Safari など | — |

| クライアント | サーバーに依頼を出す側。ブラウザがこれにあたる | 客席 |

| レスポンス | サーバーからクライアントへの返答 | 料理 |
| HTTP | ブラウザとサーバーがやり取りするときの、決められた話し方のルール | 注文の仕方の決まり |
| HTTPS | HTTP の通信内容を暗号化したもの | — |
| URL | インターネット上の場所を表す文字列 | 住所 |
| ドメイン | `example.com` のような、サーバーの名前 | — |
| ポート | 1台のコンピュータの中で、どのプログラムに繋ぐかを表す番号 | 内線番号 |

| API | プログラムから他のプログラムの機能を呼び出すための窓口 | 注文カウンター |

## JavaScript / React

| 用語 | 定義文 | たとえ |
|------|--------|--------|
| 変数 | 値に名前をつけて、あとから使い回すための仕組み | 名前を書いた箱 |
| 定数 | 一度決めたら変えない値につける名前。`const` で作る | — |
| 型 | 値の種類（数値・文字列など） | — |
| 関数 | よく使う処理に名前を付けて、いつでも呼び出せるようにしたもの | 自動販売機（入れると出てくる） |
| 引数（ひきすう） | 関数に渡す値 | 自販機に入れるお金 |
| 戻り値 | 関数が返してくる結果の値 | 出てくる商品 |
| 配列 | 複数の値を順番に並べて1つにまとめたもの | 番号付きのロッカー |
| オブジェクト | 名前と値の組を、まとめて1つにしたもの | 名札付きの引き出し |
| メソッド | オブジェクトに属している関数 | — |
| 非同期処理 | 結果が返ってくるのを待たずに、先に次の処理を進めるやり方 | 注文して席で待つ |
| Promise | 非同期処理の「あとで結果が来る」という約束を表すもの | 呼び出しベル |
| モジュール | 機能ごとにファイルを分け、必要なものだけ他のファイルから使えるようにする仕組み | — |
| Node.js | ブラウザの外でも JavaScript を動かせるようにしたもの | — |
| npm | Node.js 用のパッケージマネージャ | — |
| React | 画面を「部品」の組み合わせで作るための JavaScript のライブラリ | — |
| コンポーネント | 画面の一部分を、見た目と動きごと1つにまとめた部品 | レゴブロック |
| JSX | JavaScript の中に HTML のような書き方を混ぜられる記法 | — |
| props | 親コンポーネントから子コンポーネントへ渡す値 | 部品に貼るラベル |
| state（状態） | コンポーネントが自分で持っていて、変わると画面が描き直される値 | ホワイトボードの数字 |
| フック | `use` で始まる React の特別な関数。state などの機能を使えるようにする | — |
| レンダリング | React が画面に表示する内容を組み立て直すこと。描画 | — |
| 再レンダリング | state や props が変わったときに、React が画面を作り直すこと | — |
| 副作用 | 画面の組み立て以外の処理（データ取得、タイマー設定など） | — |
| ビルド | 書いたコードを、ブラウザが実行できる形に変換してまとめること | — |
| Vite | React のプロジェクトを作り、開発中の自動反映やビルドを行う道具 | — |

## Python / FastAPI

| 用語 | 定義文 |
|------|--------|
| インタプリタ | ソースコードを1行ずつ読んで実行するプログラム。`python` コマンドがこれ |
| REPL | 1行入力するたびに結果が返ってくる対話モード |
| 仮想環境（venv） | プロジェクトごとにライブラリを分けて入れるための隔離された領域 |
| pip | Python 用のパッケージマネージャ |
| インデント | 行頭の字下げ。Python ではこれが処理のまとまりを表す |
| リスト | 複数の値を順番に並べたもの（JavaScript の配列にあたる） |
| 要素 | リストやタプルに入っている1つ1つの値 |
| タプル | 複数の値を順番に並べたもので、作ったあと中身を変えられないもの |
| 辞書（dict） | キーと値の組をまとめたもの（JavaScript のオブジェクトにあたる） |
| キー | 辞書から値を取り出すための名前 |
| 集合（set） | 重複しない値の集まり。順番を持たない |
| ミュータブル | 作ったあとから中身を変えられる性質（リスト・辞書・集合がこれにあたる） |
| アンパック | まとまった値の中身を取り出して、それぞれの変数に配ること |
| 内包表記 | リストや辞書を、`for` を使って1行で組み立てる書き方 |
| クラス | 同じ性質を持つデータと処理をまとめた設計図 |
| インスタンス | クラスという設計図から作られた実物 |
| 例外 | 実行中に起きた問題を表すオブジェクト。`try` / `except` で受け止める |
| 型ヒント | 変数や関数に「この型のはず」と注記を書く仕組み |
| 型チェッカー | ソースコードを実行せずに読んで、型の矛盾を報告する道具。mypy や pyright がこれ |
| 静的型チェック | プログラムを動かさずに、型が合っているかを調べること |
| リンタ | コードを実行せずに読んで、規約違反や怪しい書き方を指摘する道具 |
| フォーマッタ | コードの空白や改行を、決められた形に自動で整える道具 |
| TOML | 設定を書くためのファイル形式。`pyproject.toml` で使う |
| エンドポイント | API のうち、特定の URL とメソッドの組で呼び出せる1つの窓口 |
| ルーティング | どの URL のリクエストをどの処理に渡すかの割り当て |
| バリデーション | 受け取ったデータが正しい形式かを検査すること |
| 依存性注入（DI） | 処理に必要な部品を、外から渡してもらう作り方 |

## 更新ルール

- 新しい用語を本文で初出させるときは、**先にここへ登録する**
- 定義文は**1文**にする。2文になったら、たとえ列に逃がす
- 同じ概念に複数の呼び方がある場合、**このテキストで使う1つ**を決めて書く
