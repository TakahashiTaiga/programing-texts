# 執筆タスク実行手順書（RUNBOOK）

このリポジトリの執筆を、**1回の実行で1タスクずつ**進めるための手順書です。
Claude のクラウドルーティン（定期実行エージェント）に、
下記のプロンプトをそのまま設定して回します。

- タスクの一覧と進捗：[`TASKS.md`](./TASKS.md)
- 章立て（何を書くか）：各テキストの `README.md`

---

## 1. この仕組みの考え方

```
docs/writing-tasks/TASKS.md   ← 全55タスクのキュー（状態付き）
        │
        │  ルーティンが毎回ここを読んで、
        │  「進行中」または最初の「未着手」を1件取る
        ↓
    1タスク = 1章の執筆
        ├ 本文を書く          （<book>/NN-slug.md）
        ├ 解答編に追記する    （<book>/90-answers-*.md）
        ├ curriculum-map 更新 （ai/curriculum-map.md）
        └ TASKS.md の状態を更新
        ↓
    コミット & プッシュ
```

**1回の実行で複数タスクを進めないでください。**
1タスク1コミットにすることで、内容が気に入らなければその1コミットだけ戻せます。

---

## 2. ルーティンに設定するプロンプト

**以下をそのままコピーして、ルーティンのプロンプト欄に貼り付けてください。**
毎回同じ内容で構いません。タスクの選択は Claude が `TASKS.md` を見て判断します。

```text
このリポジトリは、プログラミング未経験者向けの学習テキスト集です。
執筆タスクを1件だけ実行してください。

## 手順

1. 次のファイルを読んで、執筆ルールを把握する
   - CLAUDE.md
   - docs/writing-guidelines.md
   - docs/style-guide.md
   - docs/glossary.md
   - docs/writing-tasks/RUNBOOK.md   ← 完成条件はここに全部書いてある

2. docs/writing-tasks/TASKS.md を読み、対象タスクを1件だけ選ぶ
   - 状態が「進行中」のタスクがあれば、それを継続する
   - なければ、上から見て最初の「未着手」のタスクを選ぶ

3. 対象の本の README.md を読み、そのタスクが担当する章の
   節（X.Y）・項（X.Y.Z）をすべて確認する

4. 同じ本の直前の章（すでに執筆済みのもの）を1つ読み、
   文体・構成・分量・囲み記事の使い方を揃える
   ※ その本にまだ執筆済みの章がない場合は react-text/02-html.md を参照する

5. 本文を執筆する（RUNBOOK の「共通の完成条件」を必ず満たすこと）

6. 演習問題の解答と解説を、同じ本の解答編ファイルに追記する

7. ai/curriculum-map.md の該当行を、実際に書いた内容に合わせて更新する

8. docs/writing-tasks/TASKS.md の、そのタスクの状態を「完了」に更新する

9. 変更をコミットしてプッシュする
   コミットメッセージ例: 「R-04: react-text 第4章 JavaScript の基礎（前半）を執筆」

## 重要な制約

- 1回の実行で扱うタスクは **1件だけ**。終わったら次のタスクに進まず終了すること
- 対象読者は **プログラミング未経験者**。既知として扱ってよいのは PC の基本操作まで
- 章番号は X.Y.Z の3階層。README.md の章立てにある項を勝手に削らない
- **解答編への追記を忘れない**（これが最も抜けやすい工程）
- 学習者がその章より先の内容を使わない（ai/curriculum-map.md を参照）
- コードはすべて実行可能にする
- 環境依存の手順は Windows / macOS の両方を書く
- 日本語・ですます調

最後に、どの章のどの範囲を書いたかを1〜3行で報告してください。
```

## 3. すべてのタスク共通の完成条件

執筆タスク（`-FIN` を除く全タスク）は、次をすべて満たしたら完了です。

### 3.1 本文の構成

- [ ] frontmatter（`---` で囲んだ `title:`）がファイル先頭にある
- [ ] 章タイトルの `# 見出し` がある
- [ ] 「この章で学ぶこと」（箇条書き3〜6個、「〜できるようになる」の形）
- [ ] 「この章の前提」
- [ ] 冒頭に「つまずいたら」の囲み記事
- [ ] README.md の章立てにある**すべての節・項**が、番号付きで存在する
- [ ] 「まとめ」（箇条書き5〜12個）
- [ ] 「理解度チェック」（3〜7問）
- [ ] 「演習問題」（2〜5問、★の難易度付き）
- [ ] 「次の章へ」と次章へのリンク

### 3.2 書き方

- [ ] すべての項に `N.M.L` の番号が振られている（`####` 以下は使わない）
- [ ] 初出の専門用語すべてに、その場で1行の説明がある
- [ ] コードブロックすべてに言語指定がある
- [ ] コードを書く**ファイル名と場所**が明示されている
- [ ] コードの**実行結果**が示されている
- [ ] 環境依存の手順が Windows / macOS 両方ある
- [ ] 「よくある間違い」の囲み記事が、詰まりやすい箇所に置かれている
- [ ] 「簡単です」「すぐできます」を使っていない

### 3.3 演習問題

- [ ] 各問に「課題」「完成条件」「ヒント」の3つがある
- [ ] 完成条件が、学習者自身でチェックできる形になっている
- [ ] ヒントは方向を示すだけで、答えを書いていない
- [ ] ★☆☆ が最低1問ある（本文を少し変えればできるもの）

### 3.4 解答編（**最重要・最も抜けやすい**）

- [ ] 理解度チェックの全問に解答がある
- [ ] 演習問題の全問に解答がある
- [ ] **すべての解答に「解説」が付いている**（コードだけ置かない）
- [ ] 見出しが本文の番号と完全に対応している（`### 演習 5.2 の解答`）
- [ ] 「よくある間違い」や別解が添えられている

### 3.5 リンクと整合性

- [ ] 相対リンクがすべて実在するファイルを指している
- [ ] 前章・次章へのリンクが正しい
- [ ] `ai/curriculum-map.md` の既習範囲が、実際に書いた内容と一致している
- [ ] 対象の本の `config.yaml` の `chapters` にファイル名が含まれている

## 4. 分量の目安

| 規模 | 目安 | 1回の実行で |
|------|------|-----------|
| 小 | 3,000〜6,000字 | 余裕を持って完了する |
| 中 | 6,000〜12,000字 | 1回で完了する |
| 大 | 12,000〜20,000字 | 1回で終わらない可能性がある |

### 1回の実行で終わらなかった場合

**無理に短くまとめないでください。** 途中で切り上げて、次回に続けます。

1. そこまでの内容を保存する
2. `TASKS.md` の状態を **「進行中」** にし、備考欄に到達点を書く
   例：`進行中（4.4 まで完了。次は 4.5 繰り返しから）`
3. コミットしてプッシュする

次回の実行では、「進行中」のタスクが優先的に選ばれ、続きから再開されます。

## 5. 人間がやること（ルーティンには任せない）

| 作業 | タイミング |
|------|-----------|
| 書かれた章を読んで、内容の妥当性を確認する | 数タスクごと |
| 用語のブレ・説明の重複を直す | 1冊終わったとき（`-FIN` タスク） |
| スクリーンショット画像の撮影と配置 | 1冊終わったとき |
| Zenn への公開設定（`published: true`） | 1冊完成後 |
| 実際にコードを動かして検証する | 気になった章 |

> **AI が書いた技術文章は、コマンドやバージョンが実在しないことがあります。**
> 環境構築の章（各本の第1〜2章）だけは、**必ず自分で通しで実行して確認**してください。

## 6. ルーティンの設定方法

Claude Code のクラウドルーティン（スケジュール実行）で設定します。

- **プロンプト**：上記「2. ルーティンに設定するプロンプト」の内容
- **リポジトリ**：`TakahashiTaiga/programing-texts`
- **ブランチ**：`main`
- **頻度**：1日1〜2回程度を推奨

> **頻度を上げすぎないでください。**
> 内容を人間が読んで確認する時間が取れなくなり、
> 質の低い章が積み上がっていくことになります。

### 途中で止めたいとき

`TASKS.md` の先頭に次の1行を書き加えると、ルーティンは何もせずに終了します。

```
<!-- PAUSE: 執筆を一時停止中 -->
```

## 7. トラブルシューティング

| 症状 | 対処 |
|------|------|
| 同じタスクが2回実行された | `TASKS.md` の状態更新が漏れている。手動で「完了」にする |
| プッシュが競合した | 手元で `git pull --rebase` してから再実行 |
| 章の内容が薄い | そのタスクを「未着手」に戻し、`TASKS.md` の備考に「前回は内容が薄かった。項ごとに実例とコードを必ず入れること」と書いて再実行 |
| 解答編への追記が漏れた | 「未着手」に戻し、備考に「解答編の追記のみ」と書いて再実行 |
| 先の章の内容を使ってしまっている | `ai/curriculum-map.md` の該当行を確認し、備考に制約を明記して再実行 |
