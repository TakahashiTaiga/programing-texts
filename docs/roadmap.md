## フェーズ1：作れるようになる（現在の対象範囲）

| # | テキスト | ディレクトリ | ねらい | 状態 |
|---|---------|------------|--------|------|
| 1 | **React** | `react-text/` | 目に見えるものを作る楽しさを最初に体験する。Web の仕組み・HTML・CSS・JavaScript を含む | 執筆中 |
| 2 | **Python** | `python-text/` | 汎用言語で「処理を書く」力をつける | 準備中 |
| 3 | **FastAPI** | `fastapi-text/` | サーバー側を作り、フロントと繋ぐ | 準備中 |
| 4 | **Docker** | `docker-text/` | 環境を再現可能にする。ここで「動かない」問題が激減する | 準備中 |
| 5 | **MySQL** | `mysql-text/` | データを永続化する。設計の入り口 | 準備中 |

### なぜこの順番か

- **React が最初**：画面が動くのが一番おもしろく、挫折しにくい。
  Web の仕組み・HTML・CSS・JavaScript も同時に身につく
- **Python が2番目**：文法が読みやすく、React で覚えたプログラミングの概念
  （変数・条件・ループ・関数）を別の言語で再確認できる。ここで概念が定着する
- **FastAPI が3番目**：フロントとサーバーの両方を知り、「Web アプリ」の全体像が繋がる
- **Docker が4番目**：3冊分の環境構築を経験したあとだと、
  Docker のありがたみが実感として理解できる
- **MySQL が5番目**：Docker があれば MySQL の環境構築が一瞬で終わる

フェーズ1を終えた時点で到達する状態：

> **React + FastAPI + MySQL を Docker で動かす、CRUD ができる Web アプリを一人で作れる**

## 全体を通した設計思想

1. **必ず動くものを作る。** 概念だけの章を作らない
2. **順番に依存を積む。** 前の巻で作ったものを次の巻で使う
3. **AI を脱出装置として組み込む。** 環境構築とデバッグで止まらせない
4. **考えることは考えさせる。** 演習と解答編で自走力を作る

---

## 執筆の進め方

1 冊を「章ごとに完成させる」のではなく、次の順で進める。

1. **目次（3階層まで）を先に固める** — `README.md` に置く
2. `ai/curriculum-map.md` に既習範囲を登録する
3. 章を順に執筆する（本文 → 理解度チェック → 演習）
4. 演習を書いたら**その場で解答編にも追記する**（あとでまとめてやると必ず抜ける）
5. 1 冊書き終えたら、通しで読んで用語のブレを直す
6. Zenn に公開する（`docs/zenn-publishing.md`）
