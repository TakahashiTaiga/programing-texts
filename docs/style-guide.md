# 表記スタイルガイド

全テキストで表記を統一するためのルール。迷ったらここを見る。

---

## 1. 文体

- **ですます調**で統一する
- 一人称は使わない（「私は」「筆者は」を避ける）。読者への呼びかけは「あなた」ではなく主語を省く
- 命令形は手順にのみ使う（「〜してください」）
- 断定できることは断定する（「〜だと思います」を避ける）

---

## 2. 用語の表記

### 2.1 カタカナ語の長音

**末尾の長音符は付ける**（JIS 系ではなく一般的な表記に合わせる）。

| ✅ 使う | ❌ 使わない |
|---------|------------|
| サーバー | サーバ |
| ブラウザー → **ブラウザ** | （※ブラウザのみ例外的に長音なし） |
| コンピューター | コンピュータ |
| フォルダー → **フォルダ** | （※フォルダのみ例外的に長音なし） |
| ユーザー | ユーザ |
| ディレクトリ | ディレクトリー |

> 実務での慣用に合わせ、**ブラウザ・フォルダ・ディレクトリ・メモリ**は長音なし、
> それ以外は長音ありとする。

## 3. 記号と書式

### 3.1 コード中の識別子

本文中でコード上の名前に触れるときは**必ずバッククォート**で囲む。

> ✅ `useState` を使います / `src/App.jsx` を開きます
> ❌ useState を使います

### 3.2 強調

- **太字**：重要語の初出、注意喚起
- *斜体*：使わない（日本語で読みにくいため）
- ==ハイライト==：使わない

### 3.3 引用ブロック

用途を統一する。

```markdown
> **よくある間違い**
> 本文

> **補足**
> 本文（読み飛ばしてよい情報）

> **注意**
> 本文（守らないと動かない情報）

> **つまずいたら**
> 本文（AI に相談を促す）
```

### 3.4 括弧

- 全角括弧 `（）` を使う（半角括弧は英数字のみの補足で使う）
- 読みがな：**変数**（へんすう）のように初出時のみ

### 3.5 数字

- 半角数字を使う
- 「1つ」「2番目」のように単位が日本語なら半角数字＋日本語

### 4.4 シェルコマンド

OS ごとにタブではなく**見出しで分ける**（Zenn ではタブが使えないため）。

````markdown
```bash
node --version
```
````

コマンドの前に `$` や `>` を付けない（コピペの邪魔になる）。

## 5. リンク

- 章間リンクは相対パス：`[第3章 CSS](./03-css.md)`
- 解答編へのリンクはアンカー付き：`[解答編](./90-answers-part1.md#第2章)`
- 外部リンクは**公式ドキュメントを優先**する。個人ブログは原則リンクしない
- リンク切れを防ぐため、章ファイル名は一度決めたら変えない

---

## 6. 画像

### 6.1 スクリーンショット

- 保存先：`<book>/images/<章番号>-<内容>.png`（例：`images/01-vscode-install.png`）
- 代替テキストを必ず書く：`![VS Code のインストール画面](./images/01-vscode-install.png)`
- スクリーンショットは**OS の言語を日本語**に揃える
- 個人情報（ユーザー名・パス）が写り込まないようにする

### 6.2 図解（Mermaid / SVG）

詳しい方針は [`writing-guidelines.md`](./writing-guidelines.md) の「6. 図解」を参照。ここでは置き場所のみ：

- 流れ・構造・関係を表す図は、まず本文中に **Mermaid コードブロック**で書く（画像ファイル不要）
- Mermaid で表現できない図（ボックスモデルなど）は SVG で作図し、**PNG に変換してから**本文で参照する
  - 編集用の原本：`<book>/images/svg-src/NN-slug.svg`
  - 本文が参照する完成品：`<book>/images/NN-slug.png`
- **`.svg` ファイルを本文から直接 `![]()` で参照しない**（Zenn は `.svg` を画像として認識しないため）

## 7. 章番号の付け方

```markdown
# 第2章 HTML — 情報の骨組み      ← h1（章タイトル。番号は「第N章」）
## 2.1 タグと要素                 ← h2（節）
### 2.1.1 タグの書き方            ← h3（項）
#### （使わない）                 ← h4 以下は使わない
```

**h4 以下を使わない**理由：番号が4階層になると学習者が伝えにくくなるため。
細分化が必要になったら、節を分けて対応する。
