## 0.2 AI サポートの準備

### 0.2.1 なぜ AI を使うのか

プログラミングの独学で人が挫折する原因は、だいたい次の2つです。

**1. 環境構築で詰まる**

本のとおりにやったのに、なぜかインストールできない。
コマンドを打ったら「そんなコマンドはありません」と言われる。
検索しても、出てくる記事は3年前のもので、書いてあるとおりにやっても動かない。

**これは、あなたの能力とはまったく関係ありません。**
使っている OS、バージョン、インストール済みの他のソフト……
無数の組み合わせがあり、本にすべてを書くことは物理的に不可能なのです。

とくに Python は、**パソコンに最初から古い Python が入っていることがある**、
**「PATH を通す」設定を忘れやすい**（第1章で扱います）など、
環境構築でつまずきやすい言語です。だからこそ AI の助けが効きます。

**2. エラーの意味がわからない**

赤い英文が大量に出てきて、何が起きているのか見当もつかない。
経験者なら1行読んだだけで原因がわかるものでも、
未経験者にとっては「何がわからないのかもわからない」状態になります。

---

この2つは、**生成 AI（せいせいエーアイ。文章やコードを作り出す AI）が非常に得意とする領域**です。
あなたの環境で起きているエラーを貼り付ければ、
あなたの状況に合わせた手順を出してくれます。

このテキストは、**AI がそばにいることを前提**に書かれています。
「詰まったら AI に聞く」を、遠慮せずやってください。

> **ただし、何でも AI に聞けばいいわけではありません**
> ロジック（プログラムの筋道の組み立て方）を考える部分まで AI に任せると、
> いつまでも自分で書けるようになりません。
> そこで、**この後セットアップする指示ファイル**が効いてきます。
>
> このファイルを読み込ませた AI は、
> **「考える価値のあることは考えさせ、考える価値のないことは全部やってくれる」**
> という振る舞いをします。演習問題の答えは教えず、ヒントだけを段階的に出してくれます。

## 0.3 JavaScript との違い

**この節は、react-text（1冊目）を読み終えた人向けの「近道の地図」です。**
Python がはじめての人は、[0.3.3](#033-react-text-を読んでいない人へ) だけ読んで、
表そのものは読み飛ばして構いません（第2章以降でゼロから説明します）。

### 0.3.1 同じ概念、違う書き方

プログラミングで大事な「考え方」は、言語が変わってもほとんど同じです。

- 値に名前を付けて使い回す（**変数**）
- 条件によって処理を分ける（**条件分岐**）
- 同じ処理を繰り返す（**繰り返し**）
- 処理に名前を付けて呼び出せるようにする（**関数**）

これらは JavaScript にも Python にもあります。
違うのは**書き方（構文。プログラムの書き方の決まり）**だけです。

たとえば「1から3までを順に画面に出す」処理を、両方の言語で書いてみます。

`JavaScript（react-text で学んだ書き方）`

```js
for (let i = 1; i <= 3; i++) {
  console.log(i);
}
```

`Python（この本で学ぶ書き方）`

```python
for i in range(1, 4):
    print(i)
```

実行結果（どちらも同じ）:

```text
1
2
3
```

やっていることは同じ「3回繰り返して数字を出す」です。
ですが、見た目はかなり違います。目立つ違いは次の3つです。

1. **波かっこ `{ }` がない。** Python では、行頭の**字下げ（インデント）**で
   「どこからどこまでが繰り返しの中身か」を表します（第2章で詳しく扱います）
2. **文の終わりにセミコロン `;` を付けない**
3. **画面に出す命令が `console.log` ではなく `print`**

> **補足：どちらが正しいということはない**
> 「Python のほうが優れている」わけでも、その逆でもありません。
> 目的に応じて言語を選ぶだけです。2つ目の言語を学ぶ本当の目的は、
> **「この部分は言語ごとの書き方の違いで、この部分はどの言語でも共通の考え方だ」**と
> 見分けられるようになることです。

### 0.3.2 JavaScript / Python 対応表

react-text で学んだ書き方が、Python ではどう変わるのかを一覧にします。
**いま覚える必要はありません。** 各章を読むときに、ここへ戻ってきて確認する「地図」として使ってください。
右端の列に、詳しく学ぶ章を書いてあります。

| やりたいこと | JavaScript | Python | 詳しく学ぶ章 |
|------------|-----------|--------|:----------:|
| 変数を作る | `let x = 1;` / `const x = 1;` | `x = 1`（`let`/`const` にあたるものはない） | 2.1 |
| 変数名の付け方 | `userName`（キャメルケース） | `user_name`（スネークケース） | 2.1 |
| 画面に出力する | `console.log(x)` | `print(x)` | 2.5 |
| 文字列に値を埋め込む | `` `合計は${x}円` `` | `f"合計は{x}円"` | 2.4 |
| 等しいか比べる | `x === y` | `x == y`（`===` はない） | 2.3 |
| 「かつ / または / でない」 | `&&` / `\|\|` / `!` | `and` / `or` / `not` | 2.3 |
| ブロックの範囲を表す | 波かっこ `{ }` | 行頭のインデント（字下げ） | 2.6 |
| 「値がない」ことを表す | `null` / `undefined` | `None`（1つだけ） | 2.2 |
| 真・偽 | `true` / `false` | `True` / `False`（先頭が大文字） | 2.2 |
| 順番に並んだ値のまとまり | 配列 `[1, 2, 3]` | リスト `[1, 2, 3]` | 4.1 |
| 名前と値の組のまとまり | オブジェクト `{ name: "佐藤" }` | 辞書 `{"name": "佐藤"}` | 4.3 |
| 配列を1件ずつ変換する | `arr.map(x => x * 2)` | 内包表記 `[x * 2 for x in arr]` | 4.5 |
| 関数を定義する | `function f(a) { ... }` | `def f(a):` | 5.1 |

たとえば、第2章で `f"..."`（f-string。文字列に値を埋め込む書き方）が出てきたとき、
「これは JavaScript のテンプレートリテラル `` `...${x}...` `` にあたるものだな」と
この表で確認できれば、理解がぐっと速くなります。

> **注意：似ているけれど、同じではない**
> 「Python のリストは JavaScript の配列にあたる」と対応づけられますが、
> **できること・書き方の細部は違います。** 対応表はあくまで「入り口をつかむための地図」です。
> 細かい違いは各章の本文で説明するので、表だけで分かった気にならないでください。

## 0.4 学習の進め方

### 0.4.1 必ず手を動かす

**読むだけでは絶対に身につきません。**

このテキストに出てくるコードは、**すべて自分でタイプして**ください。
コピー&ペーストではなく、手で打つことをおすすめします。

理由は3つあります。

1. **打ち間違いからエラーの読み方を学べる**
   エラーは敵ではなく、いちばんの先生です
2. **手が構文を覚える**
   考えなくても `print` や `def` と打てるようになるまでには、回数が必要です
3. **読み飛ばしができない**
   打つには読むしかありません

とくに Python は、**行頭のインデント（字下げ）に意味がある**言語です（第2章で扱います）。
これは手で打って体に入れないと、なかなか身につきません。

> 20行を超える長いコードは、コピーしても構いません。
> ただし**コピーしたあと、1行ずつ何をしているか確認**してください。

### 0.4.2 詰まったときの動き方

詰まったら、次の順番で動いてください。

**ステップ1：3分だけ自分で考える**

- エラーメッセージを**日本語に訳してみる**（AI に訳させてもよい）
- 打ち間違いがないか、コードを上から眺める
  （とくに**インデントのずれ**と、**全角スペースの混入**は Python でよくある原因です）
- 直前に何を変えたか思い出す（**動いていた状態から何を変えたか**が最大の手がかりです）

**ステップ2：AI に聞く**

3分考えてわからなければ、すぐ AI に聞いてください。粘る必要はありません。

質問するときは、**章番号を必ず添えて**ください。

```text
python-text の 2.6.3 で詰まりました。

【やろうとしたこと】
for 文で1から3まで出そうとした

【書いたコード】
for i in range(1, 4):
print(i)

【結果】
IndentationError: expected an indented block と出る

【環境】
OS: Windows 11
```

**章番号を伝えることが重要です。**
AI は「この人は 2.6.3 にいる＝まだ関数もクラスも知らない」と判断して、
あなたが理解できる範囲の言葉で答えてくれます。

質問のテンプレートは
[`ai/prompt-templates.md`](https://github.com/TakahashiTaiga/programing-texts/blob/main/ai/prompt-templates.md)
にまとめてあります。コピーして使ってください。

**ステップ3：それでも進まなければ、飛ばす**

同じところで30分以上止まったら、いったん飛ばして先に進んでください。
先の章を読んでから戻ると、あっさり解決することがよくあります。

### 0.4.3 理解度チェックと演習問題

各章の最後に2種類の問題があります。

**理解度チェック**
読んだ内容を思い出せるか確認する問題です。3〜6問あります。
すぐ答えられなければ、その節をもう一度読んでください。

**演習問題**
実際に手を動かして作る課題です。難易度を★で示しています。

| 表示 | 意味 |
|------|------|
| ★☆☆ | 本文のコードを少し変えればできる |
| ★★☆ | 本文の複数の内容を組み合わせる必要がある |
