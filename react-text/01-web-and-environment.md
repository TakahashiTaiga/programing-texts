## 1.1 プログラムとは何か

### 1.1.1 コンピュータは指示どおりにしか動かない

コンピュータは、とても速く計算できますが、**察してはくれません。**

たとえば「カップラーメンを作って」と人に頼めば、
お湯を沸かして、フタを開けて、お湯を入れて、3分待つ、
という一連の作業を勝手にやってくれます。

コンピュータにはこれができません。次のように、全部書く必要があります。

```text
1. やかんに水を 500ml 入れる
2. やかんを火にかける
3. 水が 100 度になるまで待つ
4. カップラーメンのフタを、線のところまで開ける
5. お湯を、内側の線まで注ぐ
6. フタを閉じる
7. 3分待つ
8. フタを全部開ける
```

この「指示を、抜けなく、順番どおりに並べたもの」が**プログラム**です。

**プログラム**（コンピュータへの指示を、決まった書き方で並べたもの）

プログラミングが難しく感じられる最大の理由は、
**人間なら当然わかることを、いちいち書かないといけない**ところにあります。
これは慣れの問題です。書いているうちに、必ずできるようになります。

### 1.1.2 プログラミング言語とは

コンピュータに指示を出すとき、日本語では書けません。
「3分待つ」を日本語で書いても、コンピュータには通じないからです。

そこで、**コンピュータが理解できる、決まった書き方**を使います。
これが**プログラミング言語**です。

プログラミング言語には、たくさんの種類があります。

| 言語 | よく使われる場所 |
|------|----------------|
| JavaScript | Web ページを動かす |
| Python | データ分析、AI、サーバー |
| Java | 大規模な業務システム |
| C言語 | 機械の制御、OS |
| Swift | iPhone アプリ |

**どれも「指示を並べる」という点では同じ**です。
1つ身につけば、2つ目以降はぐっと楽になります。
このテキスト集で JavaScript のあとに Python をやるのは、そのためです。

### 1.1.3 このテキストで使う言語

この本では、**Web ページを作るための3つ**を扱います。

| 名前 | 役割 | たとえるなら |
|------|------|------------|
| **HTML** | 何がどこにあるか（構造） | 建物の骨組み |
| **CSS** | どう見えるか（見た目） | 内装・塗装 |
| **JavaScript** | どう動くか（動作） | 電気・配線 |

> **補足**
> 厳密には、HTML と CSS は「プログラミング言語」ではありません。
> HTML は**マークアップ言語**（文章に印を付けて意味を持たせる言語）、
> CSS は**スタイルシート言語**（見た目を指定する言語）と呼ばれます。
> 「計算したり条件で分岐したりできるのが、プログラミング言語」と考えてください。
>
> ただし実務では細かく区別せず「HTML を書く」と言います。気にしなくて大丈夫です。

そして最後に、JavaScript をもっと便利に使うための道具として **React** を学びます。

## 1.2 Web ページが表示される仕組み

### 1.2.1 ブラウザとサーバー

ブラウザのアドレス欄に `https://example.com` と打ち込んで Enter を押すと、
ページが表示されます。このとき、裏では何が起きているのでしょうか。

登場人物は2人です。

**ブラウザ**（Web ページを見るためのソフト。Chrome、Edge、Safari など）
あなたのパソコンやスマホの中にいます。

**サーバー**（他のコンピュータからの依頼を受けて、データを返すコンピュータ）
どこか遠くのデータセンターにいます。

レストランでたとえると、こうなります。

| 登場人物 | レストランでいうと |
|---------|-----------------|
| ブラウザ | 客席にいるお客さん |
| サーバー | 厨房 |

お客さんは厨房に入りません。注文を出して、料理が運ばれてくるのを待つだけです。

### 1.2.2 リクエストとレスポンス

ブラウザとサーバーのやり取りは、次の2つで成り立っています。

**リクエスト**（クライアントからサーバーへの依頼）＝ 注文
**レスポンス**（サーバーからクライアントへの返答）＝ 料理

流れを追ってみましょう。

```text
1. あなたが https://example.com と入力して Enter を押す
      ↓
2. ブラウザが example.com のサーバーに「トップページをください」とリクエストを送る
      ↓
3. サーバーがそれを受け取り、HTML ファイルをレスポンスとして返す
      ↓
4. ブラウザが HTML を読んで、「CSS も必要だな」と気づき、また取りにいく
      ↓
5. 画像や JavaScript も同じように取りにいく
      ↓
6. 全部そろったところで、ブラウザが画面を組み立てて表示する
```

**重要なのは、6番の「ブラウザが組み立てる」という点です。**
サーバーは、画像として完成した「絵」を送ってくるわけではありません。
**「こう組み立ててください」という指示書（HTML/CSS/JavaScript）を送ってきて、
実際の描画はあなたの手元のブラウザがやっています。**

だからこそ、あなたのパソコンの中だけでも Web ページを作って表示できます。
**この章の最後で、サーバーなしで Web ページを表示します。**

この、ブラウザとサーバーの「話し方のルール」を **HTTP** と呼びます。

**HTTP**（ブラウザとサーバーがやり取りするときの、決められた話し方のルール）

そして、その通信内容を暗号化して盗み見られないようにしたものが **HTTPS** です。
いまはほとんどのサイトが HTTPS を使っています。

### 1.2.3 URL の読み方

`https://example.com/products/123?sort=new` という URL を分解してみます。

| 部分 | 名前 | 意味 |
|------|------|------|
| `https` | スキーム | 通信のルール（HTTPS を使う） |
| `example.com` | ドメイン | どのサーバーか（＝サーバーの名前） |
| `/products/123` | パス | そのサーバーの中のどこか |
| `?sort=new` | クエリ | 追加の条件（新着順で並べて、など） |

**ドメイン**（`example.com` のような、サーバーの名前）

住所でたとえると、ドメインが「建物名」、パスが「部屋番号」です。

> **補足：ポートと localhost**
> ときどき `http://localhost:5173` のような URL を目にします。
>
> - **localhost**（自分のパソコン自身を指す名前）
> - **:5173** は**ポート**（1台のコンピュータの中で、どのプログラムに繋ぐかを表す番号）
>
> 会社の代表電話番号がドメイン、内線番号がポート、と考えるとわかりやすいです。
> 第6章で React の開発を始めると、`localhost:5173` を毎日見ることになります。

### 1.2.4 HTML・CSS・JavaScript の役割分担

サーバーから送られてくる指示書は、役割ごとに分かれています。

**HTML — 何がどこにあるか**

```html
<h1>ネコカフェ にゃんこ</h1>
<p>営業時間: 10:00 - 20:00</p>
```

これだけだと、黒い文字が上から並ぶだけの、そっけない見た目になります。

**CSS — どう見えるか**

```css
h1 {
  color: orange;
  font-size: 32px;
}
```

見出しをオレンジ色の 32 ピクセルにする、という指定です。

**JavaScript — どう動くか**

```js
button.addEventListener("click", () => {
  alert("予約しました");
});
```

ボタンが押されたら「予約しました」と表示する、という指示です。

---

この3つは、**役割をきっちり分ける**のが基本です。

| もし分けなかったら | 何が困るか |
|------------------|-----------|
| HTML の中に色の指定を書く | 色を変えたいとき、全ページを直す羽目になる |
| 見た目の変更を JavaScript でやる | どこで見た目が決まっているのか追えなくなる |

この本でも、**第2章で HTML、第3章で CSS、第4〜5章で JavaScript** と、
1つずつ順番に学んでいきます。

## 1.3 エディタを用意する

### 1.3.1 なぜ Word ではだめなのか

プログラムは「文字だけのファイル」です。Word で書いてはいけません。

Word は、文字の大きさ・色・フォントといった**装飾の情報**を、
見えないところにたくさん埋め込んで保存します。
コンピュータがプログラムとして読もうとすると、その装飾情報が邪魔になって読めません。

必要なのは、**装飾を一切持たない、純粋な文字だけのファイル**です。
これを**テキストファイル**と呼びます。

Windows の「メモ帳」でも書けますが、実際には**エディタ**を使います。

**エディタ**（ソースコードを書くための道具）

エディタには、プログラムを書くための助けが詰まっています。

- 文法に応じて色を付けてくれる（見やすい）
- 打ち間違いを赤い波線で教えてくれる
- 途中まで打つと候補を出してくれる
- ファイルの一覧をサイドバーに表示してくれる

この本では **VS Code**（ブイエス・コード）を使います。無料で、いちばん広く使われています。

### 1.3.2 VS Code をインストールする

1. ブラウザで https://code.visualstudio.com/ を開く
2. 大きな青いダウンロードボタンをクリック
   （自動で OS が判定されます。Windows なら「Download for Windows」）
3. ダウンロードされたファイルを開いて、インストーラーを進める

**Windows の場合、インストール中に出る選択肢**

次の項目には、**すべてチェックを入れてください**。あとで便利になります。

- [x] 「エクスプローラーのファイル コンテキスト メニューに [Code で開く] アクションを追加する」
- [x] 「エクスプローラーのディレクトリ コンテキスト メニューに [Code で開く] アクションを追加する」
- [x] 「サポートされているファイルの種類のエディターとして、Code を登録する」
- [x] 「PATH への追加（再起動後に使用可能）」 ← **これは特に重要です**

**macOS の場合**

ダウンロードした `.zip` を展開すると `Visual Studio Code.app` が出てきます。
これを**「アプリケーション」フォルダにドラッグ**してください。
ダウンロードフォルダのまま使うと、あとで不具合の原因になります。

### 1.3.3 日本語化する

初期状態では英語表示です。日本語にしましょう。

1. VS Code を起動する
2. 左側の縦に並んだアイコンのうち、**四角が4つ並んだアイコン**（拡張機能）をクリック
3. 検索欄に `Japanese` と入力
4. **「Japanese Language Pack for Visual Studio Code」** の「Install」をクリック
5. 右下に「Change Language and Restart」というボタンが出るのでクリック
6. VS Code が再起動して、日本語になる

> **補足**
> 英語のままでも問題ありません。むしろ、英語のメニューに慣れておくと、
> 検索で情報を探すときに有利です。好みで選んでください。
> この本では日本語表示を前提に説明します。

### 1.3.4 拡張子を表示する（Windows は必須）

**Windows を使っている人は、この設定を必ずやってください。**
やらないと、この先ほぼ確実にトラブルになります。

**拡張子**（ファイル名の末尾に付く `.html` `.js` などの部分。ファイルの種類を表す）

Windows は初期設定で、この拡張子を**隠して**しまいます。
すると、`index.html` を作ったつもりが、実際には `index.html.txt` という
別のファイルになっていた、という事故が起きます。
画面上はどちらも `index` としか見えないので、原因に気づけません。

**設定手順（Windows 11）**

1. エクスプローラー（フォルダの画面）を開く
2. 上部のメニューから **「表示」** をクリック
3. **「表示」→「ファイル名拡張子」** にチェックを入れる

**設定手順（Windows 10）**

1. エクスプローラーを開く
2. 上部の **「表示」** タブをクリック
3. **「ファイル名拡張子」** にチェックを入れる

設定後、ファイル名が `index.html` のように表示されれば成功です。

> **macOS の場合**
> Finder のメニューから「Finder」→「設定」→「詳細」タブ →
> 「すべてのファイル名拡張子を表示」にチェック。
> macOS では隠れていても事故は起きにくいですが、入れておくと確実です。

## 1.4 ターミナルに慣れる

### 1.4.1 ターミナルとは

**ターミナル**（文字でコンピュータに命令するための画面）

ふだんパソコンを使うときは、アイコンをクリックしたり、
ドラッグしたりして操作します。これを **GUI**（グラフィカル・ユーザー・インターフェース）と呼びます。

一方、**文字で命令を打ち込んで操作する**方法もあります。
これが **CUI**（キャラクタ・ユーザー・インターフェース）で、その画面がターミナルです。

黒い画面に白い文字が並ぶ様子から、多くの初学者が怖がる場所です。
ですが、やっていることは単純です。

| GUI（マウス操作） | CUI（ターミナル） |
|-----------------|------------------|
| フォルダをダブルクリックして開く | `cd フォルダ名` と打つ |
| フォルダの中身を見る | `ls` と打つ |
| 右クリック→新規作成→フォルダ | `mkdir フォルダ名` と打つ |

**同じことを、別のやり方でやっているだけ**です。

> **なぜターミナルを使うのか**
> 開発の道具の多くが、ターミナルからしか使えないからです。
> また、慣れるとマウスより圧倒的に速く、
> 「同じ作業を100回繰り返す」といったことも一瞬でできます。

### 1.4.2 ターミナルを開く

**Windows：PowerShell を開く**

1. スタートボタンを右クリック
2. 「ターミナル」または「Windows PowerShell」をクリック

> **注意**
> Windows には「コマンドプロンプト」という似た画面もありますが、
> **この本では PowerShell を使います。** 打つコマンドが一部違うためです。
> 起動した画面の先頭に `PS C:\Users\...>` と表示されていれば PowerShell です。

**macOS：ターミナルを開く**

1. `command` + `スペース` で Spotlight を開く
2. `ターミナル` と入力して Enter

---

**VS Code の中でターミナルを開くこともできます。こちらのほうが便利です。**

VS Code のメニューから **「ターミナル」→「新しいターミナル」**
（ショートカット：Windows は `Ctrl` + `Shift` + `@`、macOS は `control` + `shift` + `@`）

VS Code の下半分にターミナルが出てきます。
**エディタとターミナルを行き来しなくていいので、これからはこの方法を使ってください。**

### 1.4.3 いまどこにいるか確認する

ターミナルを使ううえで、**いちばん大事な考え方**です。

ターミナルは常に、**どこか1つのディレクトリの中にいます。**
これを**カレントディレクトリ**（現在地）と呼びます。

**ディレクトリ**（ファイルをまとめて入れておく入れ物。Windows の画面上では「フォルダ」と表示される）

エクスプローラーで「いまどのフォルダを開いているか」と同じことです。
違いは、**画面に表示されないので、自分で意識する必要がある**ことだけです。

現在地を確認するコマンドを打ってみましょう。

**Windows（PowerShell）**

```powershell
pwd
```

**macOS / Linux**

```bash
pwd
```

```text
実行結果の例（Windows）:
Path
----
C:\Users\yamada

実行結果の例（macOS）:
/Users/yamada
```

`pwd` は **p**rint **w**orking **d**irectory（作業中のディレクトリを表示）の略です。

> **これが本当に大事です**
> この先、「コマンドを打ったのにファイルが見つからない」というエラーが必ず起きます。
> そのとき原因の 9 割は、**現在地が想定と違っている**ことです。
> 困ったらまず `pwd` を打つ癖をつけてください。

### 1.4.4 移動する・一覧を見る

**中身を一覧表示する**

**Windows（PowerShell）**

```powershell
ls
```

**macOS / Linux**

```bash
ls
```

```text
実行結果の例:
Desktop
Documents
Downloads
Pictures
```

`ls` は **l**i**s**t（一覧）の略です。

**移動する**

```powershell
cd Desktop
```

`cd` は **c**hange **d**irectory（ディレクトリを変更）の略です。

もう一度 `pwd` を打つと、現在地が変わっているのが確認できます。

**1つ上に戻る**

```powershell
cd ..
```

`..`（ドット2つ）は「1つ上のディレクトリ」を意味する特別な書き方です。

> **入力を楽にするコツ：Tab キー補完**
> `cd Doc` まで打って **Tab キー**を押すと、`cd Documents` まで自動で補完されます。
> **打ち間違いが激減する**ので、必ず使ってください。
> 候補が複数ある場合は、Tab を連打すると順番に切り替わります。

> **もう1つのコツ：↑ キー**
> 上矢印キーを押すと、直前に打ったコマンドが出てきます。
> 同じコマンドを何度も打つときに便利です。

### 1.4.5 作業用ディレクトリを作る

この本の学習で使うディレクトリを作りましょう。

まず、デスクトップに移動します。

**Windows（PowerShell）**

```powershell
cd ~/Desktop
```

**macOS / Linux**

```bash
cd ~/Desktop
```

`~`（チルダ）は「自分のホームディレクトリ」を表す特別な記号です。

> **注意**
> OneDrive を使っている Windows では、デスクトップが
> `C:\Users\名前\OneDrive\デスクトップ` になっていることがあります。
> `cd ~/Desktop` でエラーが出たら、次を試してください。
>
> ```powershell
> cd ~/OneDrive/デスクトップ
> ```
>
> それでもだめなら、AI に「Windows で OneDrive を使っていて、
> PowerShell からデスクトップに移動できません」と聞いてください。

次に、ディレクトリを作ります。

```powershell
mkdir react-lesson
```

`mkdir` は **m**a**k**e **dir**ectory（ディレクトリを作る）の略です。

作ったディレクトリに移動します。

```powershell
cd react-lesson
```

現在地を確認しましょう。

```powershell
pwd
```

```text
実行結果の例:
C:\Users\yamada\Desktop\react-lesson
```

**この `react-lesson` が、これからの作業場所です。**

> **注意：ディレクトリ名に日本語やスペースを使わない**
> `私の練習` や `react lesson` のような名前は避けてください。
> 開発ツールの一部が、日本語やスペースを含むパスでうまく動かないことがあります。
> **半角英数字とハイフン、アンダースコアだけ**を使うのが安全です。

**このディレクトリを VS Code で開く**

```powershell
code .
```

`.`（ドット1つ）は「いまいるディレクトリ」を意味します。
つまり「いまいるディレクトリを VS Code で開け」という命令です。

> **`code` コマンドが使えない場合**
> `code : 用語 'code' は、コマンドレット...として認識されません` と出たら、
> VS Code のインストール時に「PATH への追加」にチェックを入れ忘れています。
>
> **これは典型的な環境トラブルです。AI に丸投げしてください。**
>
> ```text
> react-text の 1.4.5 で、PowerShell から code コマンドが使えません。
> OS: Windows 11
> エラー: code : 用語 'code' は、コマンドレット、関数、スクリプト ファイル、
> または操作可能なプログラムの名前として認識されません。
> ```
>
> 代わりに、VS Code のメニューから「ファイル」→「フォルダーを開く」で
> `react-lesson` を選んでも同じことができます。

### 1.4.6 ターミナルでよくあるエラー

これから何度も遭遇するエラーを、先に知っておきましょう。

**その1：コマンドが見つからない**

```text
node : 用語 'node' は、コマンドレット、関数、スクリプト ファイル、
または操作可能なプログラムの名前として認識されません。
```

```text
zsh: command not found: node
```

**意味**：そんな名前の命令は知らない、と言われています。

**原因**：
1. そのソフトがインストールされていない
2. インストールされているが、**PATH** に登録されていない

**PATH**（ターミナルがコマンドを探しに行く場所の一覧。ここに登録されていないとコマンドが見つからない）

**これはあなたのせいではありません。AI に投げてください。**

**その2：そのようなファイルまたはディレクトリはありません**

```text
cd : パス 'C:\Users\yamada\Desktp' が存在しないため検出できません。
```

```text
cd: no such file or directory: Desktp
```

**意味**：指定した場所が見つからない。

**原因**：ほぼ確実に、**打ち間違い**か、**現在地の勘違い**です。

**対処**：
1. `pwd` で現在地を確認する
2. `ls` でそこに何があるか確認する
3. Tab キー補完を使って打ち直す

**その3：PowerShell でスクリプトが実行できない（Windows）**

```text
このシステムではスクリプトの実行が無効になっているため、
ファイル ... を読み込むことができません。
```

**意味**：Windows のセキュリティ設定で、スクリプトの実行がブロックされています。

**対処**：PowerShell で次を実行します。

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

確認を求められたら `Y` を入力して Enter。

> これも典型的な環境トラブルです。よくわからなければ AI に聞いてください。

## 1.5 Node.js を用意する

### 1.5.1 Node.js とは

JavaScript は本来、**ブラウザの中でしか動かない**言語でした。

**Node.js** は、その JavaScript を**ブラウザの外でも動かせるようにしたもの**です。

「でも、私が作るのはブラウザで動く Web ページですよね？」
——— そのとおりです。では、なぜ Node.js が必要なのでしょうか。

理由は、**開発を助ける道具が Node.js の上で動く**からです。

| Node.js の上で動く道具 | 何をしてくれるか |
|----------------------|----------------|
| **npm** | ライブラリをインストールする |
| **Vite** | 開発中、保存すると自動でブラウザを更新してくれる |
| ビルドツール | 書いたコードを、ブラウザ向けに最適化してまとめる |

**npm**（Node.js 用のパッケージマネージャ）
**パッケージマネージャ**（ライブラリのインストール・更新・削除を管理する道具）

料理でいうと、Node.js は**厨房**です。
最終的にお客さんに出す料理（Web ページ）は客席で食べられますが、
それを作るための厨房が必要、というイメージです。

**この本では第6章から本格的に使います。** いまは準備だけしておきましょう。

### 1.5.2 インストールする

1. ブラウザで https://nodejs.org/ を開く
2. **「LTS」** と書かれたほうのボタンをクリックしてダウンロード
   （LTS = Long Term Support。長期間サポートされる安定版です）
3. ダウンロードしたファイルを開いて、インストーラーを進める
4. **選択肢はすべて初期状態のまま**で進んで構いません

> **注意：LTS を選ぶこと**
> 「Current」と書かれた最新版もありますが、こちらは新機能を試すためのものです。
> ライブラリが対応していないことがあるので、**必ず LTS を選んでください。**

> **注意：インストール後、ターミナルを開き直す**
> インストール後、**開いているターミナルをいったん全部閉じて、開き直してください。**
> 開きっぱなしのターミナルには、新しい設定（PATH）が反映されません。
>
> これを知らずに「インストールしたのに動かない」と悩む人が非常に多いです。
> VS Code も、いったん終了して起動し直すのが確実です。

### 1.5.3 動作確認する

ターミナルを開き直してから、次を実行します。

**Windows（PowerShell）**

```powershell
node --version
```

**macOS / Linux**

```bash
node --version
```

```text
実行結果の例:
v22.11.0
```

数字は違って構いません。**`v22` 以上**であれば大丈夫です。

続いて npm も確認します。

```powershell
npm --version
```

```text
実行結果の例:
10.9.0
```

両方ともバージョン番号が表示されれば、準備完了です。

> **執筆時点の環境**
> このテキストは Node.js v22 系で動作確認しています。
> もっと新しいバージョンでも基本的に問題ありませんが、
> うまくいかない場合は AI に「Node.js のバージョンは v24 です」と伝えてください。

### 1.5.4 うまくいかないとき

**`node --version` でエラーが出る場合**

そのまま AI に投げてください。次の情報を添えると解決が早くなります。

```text
react-text の 1.5.3 で詰まりました。

【やったこと】
nodejs.org から LTS 版をインストールし、ターミナルを開き直した

【実行したコマンド】
node --version

【出たエラー（全文）】
node : 用語 'node' は、コマンドレット、関数、スクリプト ファイル、
または操作可能なプログラムの名前として認識されません。名前が正しく記述されて
いることを確認し、パスが含まれている場合はそのパスが正しいことを確認してから、
再試行してください。

【環境】
OS: Windows 11
ターミナル: PowerShell
```

**よくある原因**

| 原因 | 対処 |
|------|------|
| ターミナルを開き直していない | いったん全部閉じて開き直す。それでもだめなら PC を再起動 |
| PATH に登録されていない | AI に手順を出してもらう |
| 管理者権限が必要だった | インストーラーを右クリック→「管理者として実行」 |
| 会社の PC でインストールが制限されている | 情シス部門に相談。または AI に代替手段を聞く |

> **ここで時間を使わないでください**
> 環境構築は学習内容ではありません。**AI に全部やってもらってください。**
> 「自力で解決したほうが力がつくのでは」と思うかもしれませんが、
> ここに関しては違います。プロでも、環境トラブルは検索と質問で解決します。

## 1.6 はじめての Web ページ

準備が整いました。実際に Web ページを作ってみましょう。

### 1.6.1 ファイルを作る

VS Code で `react-lesson` ディレクトリを開いている状態から始めます。
（開いていなければ、「ファイル」→「フォルダーを開く」で開いてください）

1. VS Code の左サイドバーで、**「REACT-LESSON」** という見出しの右側にマウスを乗せる
2. **新しいファイル**のアイコン（紙に + が付いたもの）をクリック
3. ファイル名に `index.html` と入力して Enter

`index.html` という空のファイルが開きます。ここに次のコードを**手で打って**ください。

`index.html`

```html
<!DOCTYPE html>
<html lang="ja">
  <head>
    <meta charset="UTF-8" />
    <title>はじめてのページ</title>
  </head>
  <body>
    <h1>はじめての Web ページ</h1>
    <p>これは私が作った最初のページです。</p>
  </body>
</html>
```

打ち終わったら、**保存**します。

- Windows: `Ctrl` + `S`
- macOS: `command` + `S`

> **いま何を書いたのか**
> 詳しい説明は第2章でします。いまは次の3つだけ知っておいてください。
>
> - `<h1>` は大見出し
> - `<p>` は段落
> - `<meta charset="UTF-8" />` は「このファイルは UTF-8 という文字の形式で書かれています」という宣言。**これがないと日本語が文字化けします**

> **タブとスペースについて**
> コードの字下げ（インデント）は、見やすさのためのものです。
> ずれていても動きますが、**揃えておくと圧倒的に読みやすくなります。**
> VS Code なら、`Shift` + `Alt` + `F`（macOS は `Shift` + `Option` + `F`）で
> 自動的に整形してくれます。

### 1.6.2 ブラウザで開く

作った HTML ファイルをブラウザで表示します。方法は2つあります。

**方法A：エクスプローラー / Finder からダブルクリック**

`react-lesson` ディレクトリの中の `index.html` をダブルクリックすると、
ブラウザで開きます。

**方法B：ターミナルから開く**

**Windows（PowerShell）**

```powershell
start index.html
```

**macOS**

```bash
open index.html
```

---

どちらの方法でも、ブラウザに次のように表示されるはずです。

```text
はじめての Web ページ

これは私が作った最初のページです。
```

**おめでとうございます。あなたが書いた最初の Web ページです。**

アドレス欄を見てみてください。次のようになっているはずです。

```text
file:///C:/Users/yamada/Desktop/react-lesson/index.html
```

`https://` ではなく `file://` で始まっています。
これは「インターネット経由ではなく、**あなたのパソコンの中のファイルを直接開いている**」
という意味です。

1.2.2 で説明したとおり、Web ページの組み立てはブラウザがやっています。
だから、サーバーがなくてもこうして表示できるのです。

### 1.6.3 書き換えて反映を確かめる

VS Code に戻って、文章を書き換えてみましょう。

`index.html`

```html
    <h1>はじめての Web ページ</h1>
    <p>これは私が作った最初のページです。</p>
    <p>プログラミングを始めました。</p>
```

`<p>` の行を1つ増やしました。**保存**（`Ctrl` + `S`）してください。

そしてブラウザに戻り、**再読み込み**します。

- Windows: `F5` または `Ctrl` + `R`
- macOS: `command` + `R`

```text
はじめての Web ページ

これは私が作った最初のページです。

プログラミングを始めました。
```

追加した行が表示されました。

> **この「書く → 保存 → 再読み込み → 確認」のサイクルが、開発の基本です。**
> 一度に大量に書かず、**少し書いては確認**を繰り返してください。
> そうすれば、エラーが出たときに「直前に書いた部分が原因だ」とすぐわかります。
>
> 一度に 50 行書いてから動かすと、どこが悪いのか探すのに何倍も時間がかかります。

### 1.6.4 開発者ツールをのぞいてみる

最後に、これから毎日使うことになる道具を紹介します。

ブラウザで `index.html` を表示している状態で、次のキーを押してください。

- Windows: `F12`
- macOS: `command` + `option` + `I`

画面の右側か下側に、新しいパネルが開きます。これが**開発者ツール**（デベロッパーツール）です。

いくつかタブがありますが、いまは2つだけ覚えてください。

**「要素」タブ（Elements）**

いまブラウザが読み込んでいる HTML が表示されます。
あなたが `index.html` に書いた内容がそのまま出ているはずです。

ここに表示されている行にマウスを乗せると、
**画面上の対応する部分がハイライトされます。**
「この文字はどのタグで書かれているんだろう」と思ったときに使います。

**「コンソール」タブ（Console）**

JavaScript のエラーメッセージや、動作確認用の出力が表示される場所です。
**第4章から本格的に使います。**

> **これが最強のデバッグ道具です**
> 「画面が思ったとおりにならない」と思ったら、**まず F12 を押してください。**
>
> - コンソールに赤いエラーが出ていないか
> - 要素タブで、自分が書いたはずのタグが存在しているか
>
> この2つを確認するだけで、原因の半分は特定できます。
>
> AI に相談するときも、**コンソールに出ているエラーをコピーして貼る**と、
> 圧倒的に的確な答えが返ってきます。

## まとめ

- **プログラム**は、コンピュータへの指示を抜けなく順番に並べたもの
- Web ページは、ブラウザが**サーバーから受け取った指示書を組み立てて**表示している
  - **リクエスト**（依頼）と**レスポンス**（返答）でやり取りする
  - ルールが **HTTP**、暗号化したものが **HTTPS**
- **HTML** は構造、**CSS** は見た目、**JavaScript** は動作。役割を分ける
- **VS Code** はコードを書くための道具。Windows では**拡張子の表示設定が必須**
- **ターミナル**は文字で命令する画面。常に「現在地」がある
  - `pwd`（現在地）/ `ls`（一覧）/ `cd`（移動）/ `mkdir`（作成）
  - **Tab キー補完**を使うと打ち間違いが減る
- **Node.js** は開発の道具を動かすための土台。**LTS 版**を入れる
  - インストール後は**ターミナルを開き直す**
- HTML ファイルは、サーバーがなくてもブラウザで直接開ける（`file://`）
- **F12** で開発者ツール。エラー確認の第一手
