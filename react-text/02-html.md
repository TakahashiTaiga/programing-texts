# 第2章 HTML — 情報の骨組み

前の章で、`<h1>` や `<p>` という記号を使って Web ページを作りました。
この記号のことを**タグ**と呼び、タグを使って文章に意味を持たせる言語が **HTML** です。

この章では、HTML を「なんとなく真似する」段階から
「意味を理解して自分で組み立てる」段階に引き上げます。

## この章で学ぶこと

- タグと要素の関係を説明できるようになる
- 見出し・段落・リスト・リンク・画像を自分で書けるようになる
- 属性の役割を理解し、`href` や `src` を正しく指定できるようになる
- 相対パスと絶対パスを使い分けられるようになる
- 表とフォームを作れるようになる
- HTML に「意味」を持たせる意義を説明できるようになる

## この章の前提

- [1.6](./01-web-and-environment.md) で HTML ファイルをブラウザに表示できていること
- VS Code とターミナルが使えること

> **つまずいたら**
> 章番号（例：`2.3.4`）と、書いたコード、実際の表示を AI に伝えてください。
> HTML は「書いたのに表示されない」が起きやすいので、
> **F12 の「要素」タブでどう解釈されているか**を一緒に伝えると解決が早いです。

## 2.1 HTML の基本

### 2.1.1 タグと要素

HTML では、文章を `<` と `>` で囲んだ記号で挟みます。

```html
<h1>ネコカフェ にゃんこ</h1>
```

この `<h1>` と `</h1>` が**タグ**です。

| 名前 | 書き方 | 意味 |
|------|--------|------|
| 開始タグ | `<h1>` | ここから始まる |
| 終了タグ | `</h1>` | ここで終わる（`/` が付く） |

そして、**開始タグ + 中身 + 終了タグ** をまとめて**要素**と呼びます。

```text
<h1>ネコカフェ にゃんこ</h1>
└─┬─┘└──────┬──────┘└─┬──┘
開始タグ    中身（内容）  終了タグ
└──────────── これ全体が「h1 要素」 ────────────┘
```

タグは、中身に**意味の印を付ける**ためのものです。

| タグ | 意味 |
|------|------|
| `<h1>` | これは**大見出し**です |
| `<p>` | これは**段落**です |
| `<a>` | これは**リンク**です |

**重要な考え方**：HTML は「文字を大きくする」ためのものではありません。
「これは見出しである」という**意味**を付けるためのものです。

その結果としてブラウザが大きく表示してくれますが、
それはおまけです。大きさを変えたいときは、第3章で学ぶ CSS を使います。

> **なぜ意味を付けるのか**
> ここで付けた意味は、次のような場面で使われます。
>
> - 検索エンジンが「このページは何について書かれているか」を判断する
> - 目の不自由な方が使う読み上げソフトが「ここから新しい章です」と伝える
> - ブラウザの「リーダーモード」が本文だけを抜き出す
>
> 詳しくは 2.5.3 で扱います。

**終了タグがないタグもあります**

一部のタグは、中身を持たないため終了タグがありません。

```html
<img src="cat.png" alt="ネコの写真" />
<br />
<hr />
```

これらを**空要素**と呼びます。
末尾の ` />` は書いても書かなくても動きますが、
**この本では書く形（`<img ... />`）で統一します。**
React で書くときに必須になるためです（第6章）。

### 2.1.2 HTML ファイルの骨組み

すべての HTML ファイルは、次の形をしています。

`index.html`

```html
<!DOCTYPE html>
<html lang="ja">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>ページのタイトル</title>
  </head>
  <body>
    <h1>ここに内容を書く</h1>
  </body>
</html>
```

1行ずつ見ていきましょう。

| 行 | 意味 |
|----|------|
| `<!DOCTYPE html>` | 「このファイルは HTML です」という宣言。**1行目に必ず書く** |
| `<html lang="ja">` | ここから HTML 本体。`lang="ja"` は「日本語のページです」という宣言 |
| `<head>` | **ページの設定**を書く場所。**画面には表示されない** |
| `<meta charset="UTF-8" />` | 文字の形式は UTF-8 だ、という宣言。**ないと日本語が文字化けする** |
| `<meta name="viewport" ...>` | スマホでの表示を正しくする設定（第3章で詳しく） |
| `<title>` | ブラウザのタブに表示される文字 |
| `<body>` | **画面に表示される内容**を書く場所 |

**覚えるべきポイントは1つだけです。**

> **`<head>` は設定、`<body>` は表示内容。**
> 画面に出したいものは、すべて `<body>` の中に書きます。

> **よくある間違い**
> 文字を書いたのに何も表示されない、というときは、
> **`<head>` の中に書いてしまっている**可能性が高いです。
> `<body>` の中かどうかを確認してください。

> **VS Code の便利機能**
> 空の `.html` ファイルで `!` を入力して `Tab` キーを押すと、
> この骨組みが一気に入力されます。**毎回手打ちする必要はありません。**
> （Emmet という機能です）

### 2.1.3 入れ子構造

タグの中には、別のタグを入れられます。これを**入れ子**（ネスト）と呼びます。

```html
<body>
  <div>
    <h1>ネコカフェ にゃんこ</h1>
    <p>営業時間は 10:00 - 20:00 です。</p>
  </div>
</body>
```

`<body>` の中に `<div>` があり、その中に `<h1>` と `<p>` がある、という構造です。

**入れ子には、絶対に守るべきルールが1つあります。**

> **タグは、開いた順と逆の順で閉じる。**

```html
<!-- 正しい -->
<p><strong>重要</strong>なお知らせ</p>

<!-- 間違い（p を先に閉じている） -->
<p><strong>重要</p></strong>
```

箱を入れ子にするイメージです。
大きい箱に小さい箱を入れたら、小さい箱を先に閉じないとフタが閉まりません。

**インデント（字下げ）で構造を表す**

入れ子の深さに応じて、行頭にスペースを入れます。
**動作には影響しませんが、読みやすさが劇的に変わります。**

```html
<!-- 読みやすい -->
<div>
  <h1>タイトル</h1>
  <p>本文</p>
</div>

<!-- 読みにくい（動くけれど） -->
<div>
<h1>タイトル</h1>
<p>本文</p>
</div>
```

VS Code で `Shift` + `Alt` + `F`（macOS: `Shift` + `Option` + `F`）を押すと、
**自動で整形してくれます。** 迷ったらこれを押してください。

> **よくある間違い：閉じタグの書き忘れ**
> HTML で最も多いミスです。閉じタグを忘れると、
> **その後の要素がすべて中に入ってしまい**、表示が大きく崩れます。
>
> 画面がおかしくなったら、**まず閉じタグを疑ってください。**
> `Shift` + `Alt` + `F` で整形して、インデントがおかしい場所を探すと見つかります。

### 2.1.4 コメント

コードの中に、**ブラウザには無視されるメモ**を書けます。

```html
<!-- ここはヘッダー部分 -->
<h1>ネコカフェ にゃんこ</h1>

<!--
複数行の
コメントも書けます
-->
```

`<!--` で始まり `-->` で終わります。

コメントの使い道は2つです。

1. **自分や他の人へのメモ**：「ここは何をしている部分か」を書き残す
2. **一時的にコードを無効化する**：消さずに動作を止められる

```html
<!-- <p>この行は今は表示したくない</p> -->
```

> **ショートカット**
> 消したい行を選択して `Ctrl` + `/`（macOS: `command` + `/`）を押すと、
> コメントにしたり戻したりできます。**デバッグで頻繁に使います。**

> **注意**
> HTML のコメントは、ブラウザの「ページのソースを表示」で**誰でも読めます。**
> パスワードなど、人に見られて困る情報を書かないでください。

## 2.2 文章を組み立てるタグ

ここから、実際に使うタグを見ていきます。

練習用のファイルを作りましょう。`react-lesson` の中に `html-practice.html` を作り、
2.1.2 の骨組みを入れてください（`!` + `Tab` で一発です）。

以降のコードは、すべて `<body>` の中に書きます。

### 2.2.1 見出し

見出しには `<h1>` から `<h6>` までの6段階があります。

```html
<h1>ネコカフェ にゃんこ</h1>
<h2>メニュー</h2>
<h3>ドリンク</h3>
<h3>フード</h3>
<h2>アクセス</h2>
```

```text
表示:
ネコカフェ にゃんこ    ← 大きい
メニュー
ドリンク
フード
アクセス
```

`h` は **h**eading（見出し）の略です。数字が大きくなるほど小さい見出しになります。

**使い方のルール**

| ルール | 理由 |
|--------|------|
| `<h1>` は**1ページに1つ**だけ | そのページ全体のタイトルだから |
| **段階を飛ばさない**（`h1` の次に `h3` はダメ） | 文書の階層構造が壊れるから |
| **文字を大きくしたいだけなら使わない** | 見た目の変更は CSS の仕事 |

本の目次をイメージしてください。

```text
h1  ネコカフェ にゃんこ        ← 本のタイトル
  h2  メニュー                ← 章
    h3  ドリンク              ← 節
    h3  フード                ← 節
  h2  アクセス                ← 章
```

> **よくある間違い**
> 「この文字を大きくしたい」という理由で `<h2>` を使ってしまう。
> これをやると、見た目は良くても**文書の構造がめちゃくちゃ**になります。
> 大きくしたいだけなら `<p>` のまま、CSS で大きくします（第3章）。

### 2.2.2 段落と改行

**段落は `<p>`**

```html
<p>ネコカフェ にゃんこは、2020年に開店しました。</p>
<p>現在12匹のネコが在籍しています。</p>
```

```text
表示:
ネコカフェ にゃんこは、2020年に開店しました。

現在12匹のネコが在籍しています。
```

段落と段落の間には、自動的に余白が入ります。

**HTML は改行とスペースを無視する**

これは初学者が必ず驚くポイントです。

```html
<p>
  ネコカフェ
  にゃんこへ
  ようこそ
</p>
```

```text
表示:
ネコカフェ にゃんこへ ようこそ
```

**エディタ上で改行しても、表示では改行されません。**
連続したスペースも、1つにまとめられてしまいます。

```html
<p>スペース          たくさん</p>
```

```text
表示:
スペース たくさん
```

**どうしても改行したいときは `<br />`**

```html
<p>
  〒100-0001<br />
  東京都千代田区1-1-1<br />
  にゃんこビル 2F
</p>
```

```text
表示:
〒100-0001
東京都千代田区1-1-1
にゃんこビル 2F
```

> **`<br />` の使いすぎに注意**
> `<br />` は「住所」「詩」など、**改行そのものに意味がある場合**にだけ使います。
>
> 段落を分けたいだけなら `<p>` を2つ使ってください。
> `<br /><br />` で余白を作るのは、よくある悪い書き方です。

**水平線は `<hr />`**

```html
<h2>メニュー</h2>
<hr />
<p>ドリンク各種をご用意しています。</p>
```

内容の区切りを表します。

### 2.2.3 リスト

リストは3種類あります。

**順序なしリスト（`<ul>`）— 順番に意味がない場合**

```html
<h2>在籍しているネコ</h2>
<ul>
  <li>たま</li>
  <li>みけ</li>
  <li>くろ</li>
</ul>
```

```text
表示:
・たま
・みけ
・くろ
```

`ul` は **u**nordered **l**ist（順序なしリスト）、
`li` は **l**ist **i**tem（リストの項目）の略です。

**順序ありリスト（`<ol>`）— 順番に意味がある場合**

```html
<h2>ご利用の流れ</h2>
<ol>
  <li>受付で手を消毒する</li>
  <li>料金を支払う</li>
  <li>ネコの部屋へ入る</li>
</ol>
```

```text
表示:
1. 受付で手を消毒する
2. 料金を支払う
3. ネコの部屋へ入る
```

`ol` は **o**rdered **l**ist（順序ありリスト）の略です。
**番号は自動で振られます。** 手で `1.` と書かないでください。

> **どちらを使うか**
> 「順番を入れ替えても意味が通じるか」で判断します。
> 通じるなら `<ul>`、通じないなら `<ol>` です。

**リストは入れ子にできる**

```html
<ul>
  <li>
    ドリンク
    <ul>
      <li>コーヒー</li>
      <li>紅茶</li>
    </ul>
  </li>
  <li>フード</li>
</ul>
```

> **よくある間違い**
> 入れ子にするとき、内側の `<ul>` を `<li>` の**外**に書いてしまう。
> **`<li>` の中に入れる**のが正しい書き方です。

**説明リスト（`<dl>`）— 用語と説明の組**

```html
<dl>
  <dt>入場料</dt>
  <dd>1時間 1,200円</dd>

  <dt>営業時間</dt>
  <dd>10:00 - 20:00</dd>
</dl>
```

`dt` が用語（**d**escription **t**erm）、`dd` が説明（**d**escription **d**etails）です。
使う機会は多くありませんが、「用語と説明の組」を表すときに便利です。

### 2.2.4 強調

文章の一部を強調するタグです。

```html
<p><strong>重要</strong>：本日は<em>貸切</em>のため入場できません。</p>
```

```text
表示:
重要：本日は貸切のため入場できません。
（「重要」が太字、「貸切」が斜体）
```

| タグ | 意味 | 初期の見た目 |
|------|------|-------------|
| `<strong>` | **重要である**という強い強調 | 太字 |
| `<em>` | **そこを強く読む**というニュアンスの強調 | 斜体 |

`em` は **em**phasis（強調）の略です。

> **`<b>` と `<i>` について**
> 太字にする `<b>`、斜体にする `<i>` というタグも存在します。
> ただしこれらは「**見た目**を変えるだけ」で、意味を持ちません。
>
> **意味があるなら `<strong>` / `<em>`、見た目だけなら CSS。**
> `<b>` と `<i>` の出番はほとんどありません。

**その他のよく使うタグ**

```html
<p>コマンドは <code>npm install</code> です。</p>
<p>価格は <s>1,500円</s> 1,200円です。</p>
<p>H<sub>2</sub>O と 10<sup>3</sup></p>
```

| タグ | 意味 |
|------|------|
| `<code>` | プログラムのコード |
| `<s>` | もう正しくない内容（取り消し線） |
| `<sub>` | 下付き文字 |
| `<sup>` | 上付き文字 |

## 2.3 属性

### 2.3.1 属性の書き方

タグには、**追加の情報**を持たせられます。これを**属性**と呼びます。

```html
<a href="https://example.com">サンプルサイト</a>
```

```text
<a href="https://example.com">サンプルサイト</a>
 ↑   ↑        ↑
タグ名 属性名    属性値
```

書き方のルールは3つです。

1. **開始タグの中**に書く（終了タグには書かない）
2. `属性名="属性値"` の形で書く
3. 複数ある場合は**半角スペースで区切る**

```html
<img src="cat.png" alt="ネコの写真" width="300" />
```

> **よくある間違い**
> 属性値をクォート（`"`）で囲み忘れる。
> 値にスペースが含まれると、そこで切れてしまい正しく動きません。
>
> ```html
> <!-- 間違い -->
> <img alt=ネコの 写真 />
> <!-- 正しい -->
> <img alt="ネコの 写真" />
> ```
>
> **常に `"` で囲む**と覚えてください。

### 2.3.2 リンク

他のページへ移動するリンクは `<a>` タグで作ります。

```html
<a href="https://example.com">サンプルサイトへ</a>
```

`a` は **a**nchor（錨、つなぎ止めるもの）の略です。
`href` は **h**ypertext **ref**erence（参照先）の略です。

**別のタブで開く**

```html
<a href="https://example.com" target="_blank" rel="noopener noreferrer">
  サンプルサイトへ（別タブ）
</a>
```

| 属性 | 意味 |
|------|------|
| `target="_blank"` | 新しいタブで開く |
| `rel="noopener noreferrer"` | セキュリティ対策。`target="_blank"` とセットで書く |

> **`rel="noopener noreferrer"` は何か**
> `target="_blank"` だけを付けると、リンク先のページから
> **元のページを操作できてしまう**という問題があります。
> それを防ぐための指定です。**理由は覚えなくていいので、セットで書いてください。**

**同じサイト内の別ページへ**

```html
<a href="about.html">お店について</a>
```

**ページ内の特定の場所へ**

```html
<h2 id="access">アクセス</h2>
...
<a href="#access">アクセス情報へ</a>
```

`#` の後ろに、飛び先の `id` 属性の値を書きます（`id` は 2.3.5 で説明します）。

**メールと電話**

```html
<a href="mailto:info@example.com">メールを送る</a>
<a href="tel:0312345678">電話をかける</a>
```

### 2.3.3 画像

画像を表示するには `<img>` タグを使います。

```html
<img src="images/cat.png" alt="窓辺で眠る三毛猫" />
```

| 属性 | 意味 | 必須か |
|------|------|--------|
| `src` | 画像ファイルの場所（**s**ou**rc**e） | 必須 |
| `alt` | 画像の説明文（**alt**ernative text） | **必須** |
| `width` / `height` | 表示サイズ | 任意 |

**`alt` は必ず書いてください。** 理由は3つあります。

1. 画像が読み込めなかったときに、代わりに表示される
2. 読み上げソフトが、この文章を読み上げる（目の不自由な方が内容を理解できる）
3. 検索エンジンが画像の内容を理解できる

```html
<!-- 悪い例 -->
<img src="cat.png" alt="画像" />
<img src="cat.png" alt="" />

<!-- 良い例 -->
<img src="cat.png" alt="窓辺で眠る三毛猫のたま" />
```

> **`alt=""` を書く場合**
> 装飾目的だけの画像（意味を持たない飾り線など）は、
> 空の `alt=""` を書きます。読み上げソフトが読み飛ばしてくれます。
> **属性自体を省略するのとは意味が違う**ので注意してください。

**画像が表示されないときは**

初学者が最もつまずくのがここです。原因はほぼ**パスの間違い**です。
次の 2.3.4 で詳しく扱います。

### 2.3.4 相対パスと絶対パス

**パス**（ファイルやディレクトリの場所を表す文字列）

パスの書き方には2種類あります。

**絶対パス — 一番上から辿って書く**

```html
<img src="https://example.com/images/cat.png" />
```

インターネット上の場所を、完全な形で指定します。住所でいえば
「東京都千代田区1-1-1」のような書き方です。

**相対パス — いまいるファイルを基準に書く**

```html
<img src="images/cat.png" />
```

**「このHTMLファイルがある場所」を基準**にした書き方です。
「ここから2つ隣」のような書き方だと考えてください。

---

**相対パスの書き方**

次のようなディレクトリ構成を考えます。

```text
react-lesson/
├── index.html
├── about.html
├── images/
│   ├── cat.png
│   └── logo.png
└── pages/
    └── menu.html
```

`index.html` から見た場合：

| 書きたいもの | パス |
|------------|------|
| 同じ階層の `about.html` | `about.html` |
| `images` の中の `cat.png` | `images/cat.png` |
| `pages` の中の `menu.html` | `pages/menu.html` |

`pages/menu.html` から見た場合：

| 書きたいもの | パス |
|------------|------|
| 1つ上の `index.html` | `../index.html` |
| 1つ上の `images` の中の `cat.png` | `../images/cat.png` |

**`../` は「1つ上のディレクトリ」** を意味します。
ターミナルの `cd ..` と同じ考え方です（1.4.4 参照）。

2つ上に行きたいときは `../../` と重ねます。

---

> **よくある間違い（画像が表示されない原因トップ4）**
>
> 1. **ファイル名の大文字・小文字が違う**
>    `Cat.png` と `cat.png` は別のファイルです。
>    Windows では偶然動くことがありますが、サーバーに上げた途端に壊れます。
>    **すべて小文字で統一する**のが安全です。
>
> 2. **拡張子が違う**
>    `.jpg` と `.jpeg`、`.png` と `.PNG` は別物です。
>    Windows で拡張子が隠れていると気づけません（[1.3.4](./01-web-and-environment.md) 参照）。
>
> 3. **`/` と `\` を間違えている**
>    Windows のパスは `images\cat.png` ですが、
>    **HTML では必ず `/`（スラッシュ）** を使います。
>
> 4. **現在地の勘違い**
>    HTML ファイルの場所を基準にします。ブラウザで開いているページの場所です。

> **確認方法**
> 画像が表示されなかったら、**F12 →「コンソール」タブ**を見てください。
>
> ```text
> GET file:///C:/Users/yamada/Desktop/react-lesson/images/cat.png
> net::ERR_FILE_NOT_FOUND
> ```
>
> このように、**ブラウザが探しに行ったパス**が表示されます。
> そこに実際にファイルがあるか確認すれば、原因がすぐわかります。

> **つまずいたら**
> ```text
> react-text の 2.3.4 で画像が表示されません。
>
> 【ディレクトリ構成】
> react-lesson/
> ├── index.html
> └── images/
>     └── cat.png
>
> 【書いたコード】
> <img src="/images/cat.png" alt="ネコ" />
>
> 【コンソールのエラー】
> （F12 のコンソールに出ているものを貼る）
> ```

### 2.3.5 id と class

どのタグにも付けられる、2つの重要な属性があります。

```html
<h2 id="access">アクセス</h2>
<p class="note">※駐車場はありません</p>
<p class="note">※予約優先制です</p>
```

| 属性 | 意味 | 同じ値の重複 |
|------|------|------------|
| `id` | この要素につける**固有の名前** | **不可**（ページ内で1つだけ） |
| `class` | この要素が属する**グループ名** | **可**（何個でも） |

**たとえるなら**

- `id` は**マイナンバー**（1人に1つ、重複しない）
- `class` は**部活動**（同じ部活に何人でも所属できる）

**class は複数指定できる**

半角スペースで区切ります。

```html
<p class="note important">※重要なお知らせ</p>
```

この `<p>` は `note` グループと `important` グループの両方に属します。

**何に使うのか**

| 用途 | 主に使うもの |
|------|------------|
| CSS で見た目を指定する（第3章） | **class** |
| JavaScript で要素を取得する（第5章） | 両方 |
| ページ内リンクの飛び先（2.3.2） | **id** |

**実務では `class` を圧倒的に多く使います。**
`id` は「ページ内に1つしかない特別なもの」に限定して使ってください。

**名前の付け方**

```html
<!-- 良い例：何のためのものか分かる -->
<div class="menu-card">
<p class="error-message">

<!-- 悪い例：見た目そのものを名前にしている -->
<p class="red-text">
<div class="left-box">
```

なぜ悪いかというと、あとで「赤をやめて青にしよう」となったとき、
`red-text` という名前が嘘になってしまうからです。
**「どう見えるか」ではなく「何であるか」で名前を付けます。**

> **名前のルール**
> - 半角英数字、ハイフン `-`、アンダースコア `_` を使う
> - 数字から始めない
> - 日本語は使わない（動きますが、トラブルの元です）
> - 単語の区切りはハイフン（`menu-card`）が一般的

## 2.4 表とフォーム

### 2.4.1 表

表は複数のタグを組み合わせて作ります。

```html
<table>
  <thead>
    <tr>
      <th>名前</th>
      <th>種類</th>
      <th>年齢</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>たま</td>
      <td>三毛猫</td>
      <td>3歳</td>
    </tr>
    <tr>
      <td>くろ</td>
      <td>黒猫</td>
      <td>5歳</td>
    </tr>
  </tbody>
</table>
```

```text
表示:
名前  | 種類   | 年齢
------|--------|------
たま  | 三毛猫 | 3歳
くろ  | 黒猫   | 5歳
```

| タグ | 意味 | 略 |
|------|------|-----|
| `<table>` | 表全体 | — |
| `<thead>` | 見出し行のまとまり | **t**able **head** |
| `<tbody>` | データ行のまとまり | **t**able **body** |
| `<tr>` | 1行 | **t**able **r**ow |
| `<th>` | 見出しのセル | **t**able **h**eader |
| `<td>` | データのセル | **t**able **d**ata |

**構造の覚え方**

```text
table（表）
 └ tr（行）
    └ td（セル）
```

**行を作ってから、その中にセルを並べる**、という順番です。
「列」を作るタグはありません。各行の同じ位置にあるセルが、自動的に列になります。

> **よくある間違い**
> 各行のセル数が揃っていないと、表が崩れます。
> `<tr>` の中の `<td>` の数を、全行で同じにしてください。

**セルを結合する**

```html
<tr>
  <td colspan="2">2列分を結合</td>
  <td>通常</td>
</tr>
<tr>
  <td rowspan="2">2行分を結合</td>
  <td>A</td>
  <td>B</td>
</tr>
```

| 属性 | 意味 |
|------|------|
| `colspan="2"` | 横に2列分結合 |
| `rowspan="2"` | 縦に2行分結合 |

> **注意：レイアウトに表を使わない**
> 昔は `<table>` でページ全体のレイアウトを組む手法がありましたが、
> **現在では絶対にやりません。** レイアウトは CSS の仕事です（第3章）。
> `<table>` は「本当に表であるデータ」にだけ使ってください。

### 2.4.2 フォームの基本

ユーザーが入力するための部品をまとめたものが**フォーム**です。

```html
<form>
  <label for="name">お名前</label>
  <input type="text" id="name" name="name" />

  <label for="email">メールアドレス</label>
  <input type="email" id="email" name="email" />

  <button type="submit">送信</button>
</form>
```

**`<label>` と `for` の関係**

```html
<label for="name">お名前</label>
<input type="text" id="name" />
```

`<label>` の `for` 属性に、`<input>` の `id` を書きます。
こうすると2つが結びつき、次の効果が得られます。

1. **ラベルの文字をクリックすると、入力欄にカーソルが入る**（押しやすくなる）
2. 読み上げソフトが「お名前の入力欄です」と伝えられる

**`for` と `id` は必ずセットで書いてください。**

**`name` 属性**

```html
<input type="text" id="name" name="username" />
```

`name` は、**サーバーにデータを送るときの項目名**です。
「この入力値は `username` という名前で送ります」という宣言になります。

> **`id` と `name` の違い**
> - `id` … ページ内での識別用（`<label>` と結びつけるなど）
> - `name` … サーバーに送るときの項目名
>
> 混乱しやすいですが、**両方書くのが基本**です。
> 同じ値にしても構いません。

> **補足**
> この本では第7章で React のフォームを扱います。
> React では `name` を使わない書き方もしますが、
> **HTML の基本としては両方書く**と覚えておいてください。

### 2.4.3 いろいろな入力欄

`<input>` は `type` 属性で種類が変わります。

```html
<!-- 1行テキスト -->
<input type="text" id="name" name="name" placeholder="山田太郎" />

<!-- メールアドレス（形式チェックが入る） -->
<input type="email" id="email" name="email" />

<!-- パスワード（入力が●で隠れる） -->
<input type="password" id="pw" name="pw" />

<!-- 数値（スピンボタンが付く） -->
<input type="number" id="age" name="age" min="0" max="120" />

<!-- 日付（カレンダーが出る） -->
<input type="date" id="visit" name="visit" />

<!-- チェックボックス（複数選択可） -->
<input type="checkbox" id="agree" name="agree" />
<label for="agree">利用規約に同意する</label>

<!-- ラジオボタン（1つだけ選択） -->
<input type="radio" id="plan-a" name="plan" value="a" />
<label for="plan-a">1時間プラン</label>
<input type="radio" id="plan-b" name="plan" value="b" />
<label for="plan-b">フリープラン</label>
```

> **ラジオボタンの重要ルール**
> 同じグループにしたいラジオボタンは、**`name` を同じ値にします。**
> `name` が同じもの同士で「1つだけ選択」が働きます。
> `name` を変えてしまうと、両方選べてしまいます。

**複数行のテキスト（`<textarea>`）**

```html
<label for="message">ご要望</label>
<textarea id="message" name="message" rows="5"></textarea>
```

`<input>` ではなく別のタグです。**終了タグが必要**な点に注意してください。

**選択肢から選ぶ（`<select>`）**

```html
<label for="plan">プラン</label>
<select id="plan" name="plan">
  <option value="">選択してください</option>
  <option value="1h">1時間プラン</option>
  <option value="free">フリープラン</option>
</select>
```

**よく使う属性**

| 属性 | 意味 |
|------|------|
| `placeholder` | 入力前に薄く表示されるヒント文 |
| `required` | 入力必須にする |
| `disabled` | 入力できなくする |
| `value` | 初期値 |
| `min` / `max` | 数値・日付の範囲 |

```html
<input type="text" id="name" name="name" required placeholder="山田太郎" />
```

> **`placeholder` をラベルの代わりにしない**
> `placeholder` は入力を始めると消えてしまいます。
> 「何を入力する欄だったか」がわからなくなるので、
> **`<label>` は必ず別に書いてください。**

### 2.4.4 ボタン

```html
<button type="submit">送信する</button>
<button type="reset">クリア</button>
<button type="button">ただのボタン</button>
```

| `type` | 動作 |
|--------|------|
| `submit` | フォームを送信する（**省略時のデフォルト**） |
| `reset` | 入力内容を消す |
| `button` | 何もしない（JavaScript で動作を付ける） |

> **注意：`type` を省略しない**
> `<button>` の `type` を省略すると `submit` になります。
> フォームの中で「ただ押すだけのボタン」を作ったつもりが、
> **押すたびにページが再読み込みされる**という現象が起きます。
>
> **JavaScript で動かすボタンには、必ず `type="button"` を書いてください。**
> これは第7章の React でも同じ問題が起きます。

**フォームを実際に動かす**

いまの段階では、送信ボタンを押しても何も起きません（あるいはページが再読み込みされるだけ）。
**入力内容を実際に処理するには JavaScript が必要**で、これは第5章と第7章で学びます。

いまは「入力欄の作り方」だけ押さえておいてください。

## 2.5 意味のある構造をつくる

### 2.5.1 div と span

**それ自体には意味を持たない**、まとめるためだけのタグが2つあります。

```html
<div class="menu-card">
  <h3>ドリンクセット</h3>
  <p>1,200円</p>
</div>

<p>本日は<span class="highlight">貸切</span>です。</p>
```

| タグ | 意味 | 表示 |
|------|------|------|
| `<div>` | 意味を持たないまとまり（**div**ision） | **前後で改行される**（ブロック） |
| `<span>` | 意味を持たない、文章の一部（範囲） | **改行されない**（インライン） |

**ブロックとインライン**

これは HTML の重要な区別です。

```html
<div>あ</div><div>い</div>
```

```text
表示:
あ
い
```

```html
<span>あ</span><span>い</span>
```

```text
表示:
あい
```

| 種類 | 特徴 | 代表的なタグ |
|------|------|------------|
| **ブロック** | 横幅いっぱいに広がり、前後で改行される | `div` `p` `h1`〜`h6` `ul` `li` `table` |
| **インライン** | 中身の分だけの幅。改行されない | `span` `a` `strong` `em` `img` |

> **使い分け**
> - 領域をまとめたい（CSS でレイアウトしたい）→ `<div>`
> - 文章の一部だけ装飾したい → `<span>`

### 2.5.2 header / main / footer / section

`<div>` はどこにでも使えますが、**使いすぎると構造がわからなくなります。**

```html
<!-- これでは何がどこなのかわからない -->
<div>
  <div>
    <div>ネコカフェ にゃんこ</div>
  </div>
  <div>
    <div>...</div>
  </div>
</div>
```

そこで、**役割を表すタグ**を使います。

```html
<body>
  <header>
    <h1>ネコカフェ にゃんこ</h1>
    <nav>
      <ul>
        <li><a href="index.html">ホーム</a></li>
        <li><a href="menu.html">メニュー</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <section>
      <h2>お知らせ</h2>
      <p>本日は通常営業です。</p>
    </section>

    <article>
      <h2>ネコの紹介</h2>
      <p>三毛猫のたまは、当店の看板猫です。</p>
    </article>
  </main>

  <aside>
    <h2>関連リンク</h2>
    <ul>
      <li><a href="#">アクセス</a></li>
    </ul>
  </aside>

  <footer>
    <p>&copy; 2026 ネコカフェ にゃんこ</p>
  </footer>
</body>
```

| タグ | 意味 |
|------|------|
| `<header>` | ページ上部のまとまり（タイトル、ナビなど） |
| `<nav>` | ナビゲーション（メニューリンクの集まり） |
| `<main>` | **そのページの主要な内容**。1ページに1つだけ |
| `<section>` | 意味のまとまり。**見出しとセット**で使う |
| `<article>` | それだけで独立して成立する内容（記事、投稿） |
| `<aside>` | 補足的な内容（サイドバーなど） |
| `<footer>` | ページ下部のまとまり（著作権表示など） |

これらを**セマンティック要素**（意味を持つ要素）と呼びます。

**やっていることは `<div>` と同じです。**
見た目も変わりません。違うのは**意味が伝わるかどうか**だけです。

> **`<section>` と `<article>` の使い分け**
> - `<article>`：切り出して単体で公開しても意味が通じるもの（ブログ記事、商品、コメント）
> - `<section>`：そのページの中の1区画（「お知らせ」「アクセス」など）
>
> 迷ったら `<section>` を使ってください。
> なお **`<section>` には必ず見出し（`h2` など）を入れる**のがルールです。

**`&copy;` は何か**

`&copy;` と書くと `©` が表示されます。これを**文字実体参照**と呼びます。

| 書き方 | 表示 | 使う理由 |
|--------|------|---------|
| `&lt;` | `<` | タグの開始と区別するため |
| `&gt;` | `>` | タグの終了と区別するため |
| `&amp;` | `&` | 実体参照の開始と区別するため |
| `&copy;` | `©` | キーボードで打ちにくいため |
| `&nbsp;` | （スペース） | 途中で改行させたくないとき |

> **`<` をそのまま書くとどうなるか**
> ブラウザが「タグが始まった」と勘違いします。
> 文章として `<` を表示したいときは `&lt;` と書いてください。

### 2.5.3 なぜ意味を持たせるのか

「見た目が同じなら `<div>` でいいのでは？」と思うかもしれません。
`<div>` だけでも動きます。しかし、次の4つで差が出ます。

**1. 検索エンジンが内容を理解できる（SEO）**

検索エンジンは、`<h1>` を見て「このページの主題はこれだ」と判断し、
`<main>` を見て「ここが本文だ」と判断します。
すべてが `<div>` だと、この判断ができません。

**2. 読み上げソフトが使える（アクセシビリティ）**

目の不自由な方は、読み上げソフトで Web を利用します。
このソフトは、`<nav>` を見つけると「ナビゲーションへ移動」という
ショートカットを提供できます。`<div>` ではできません。

`<label>` と `for` の対応、`<img>` の `alt` も同じ理由です。
**これは「余裕があればやる」ことではなく、Web の基本的な要件です。**

**3. 他の人（と未来の自分）が読める**

3か月後の自分がこのコードを見たとき、
`<div class="wrapper">` の中に `<div class="inner">` が入っている構造より、
`<header>` `<main>` `<footer>` のほうが圧倒的に速く理解できます。

**4. ブラウザの機能が働く**

Safari や Firefox の「リーダーモード」は、
`<article>` や `<main>` を手がかりに本文を抜き出しています。

---

**判断の順番**

```text
1. 意味を表すタグがあるか考える → あればそれを使う（header, nav, main, section...）
2. なければ div / span を使う
```

> **完璧を目指さなくて大丈夫です**
> 実務でも「これは section か article か」で議論になります。
> **まずは `<header>` `<main>` `<footer>` の3つを使い分ける**ところから始めてください。
> それだけでも十分な効果があります。

## まとめ

- **タグ**は文章に**意味の印**を付けるもの。開始タグ + 中身 + 終了タグ = **要素**
- HTML の骨組み：`<head>` は**設定**、`<body>` は**表示内容**
  - `<meta charset="UTF-8" />` がないと日本語が文字化けする
- タグは**開いた順と逆の順で閉じる**。閉じ忘れが崩れの最大の原因
- **HTML は改行とスペースを無視する**。改行したいなら `<br />`
- 見出しは `h1`〜`h6`。**`h1` は1ページに1つ、段階を飛ばさない**
- リストは `<ul>`（順序なし）/ `<ol>`（順序あり）/ `<dl>`（用語と説明）
- **属性**はタグに追加情報を持たせる。`属性名="値"` の形で、必ずクォートで囲む
- `<a href="...">` でリンク、`<img src="..." alt="..." />` で画像
  - **`alt` は必ず書く**
- **パス**：`../` は1つ上。画像が出ないときはまず F12 のコンソールを見る
- **`id`** はページ内で固有、**`class`** はグループ（重複可）
  - 名前は「見た目」でなく「何であるか」で付ける
- 表は `table > tr > td` の入れ子。**レイアウトには使わない**
- フォーム：`<label for="x">` と `<input id="x">` は**必ずセット**
  - **JavaScript で動かすボタンには `type="button"`**
- `<div>`（ブロック）と `<span>`（インライン）は意味を持たない
- **セマンティック要素**（`header` `main` `footer` `section` など）で意味を持たせる
  - SEO、読み上げソフト、可読性のために重要
